# Backend 1.0.0 readiness audit

**Audit date:** 2026-11-04  
**Backend source version:** `1.0.0`  
**Host API reported by Backend:** `1.0.0`  
**Frontend Protocol:** `1.0.0`  
**Kernel C ABI inspected:** `1.1.0`

**Product integration decision: NOT READY for production use.** Backend source/API and the shared Protocol are versioned `1.0.0`; the paired Runtime `1.0.0` candidate advertises the same Protocol and contains the matching event/line-window services. The remaining gates are live Lua/Kernel verification, concrete OS transport and native platform results.

## 1. Implemented in this source snapshot

- Standalone deterministic-CBOR codec, canonical validation, 4-byte big-endian framing and callback-based partial stream I/O.
- Schema validation for all 33 Protocol 1.0.0 messages.
- Bounded client queues, sequence validation, Driver/Observer permissions, FIFO promotion, state coalescing, atomic snapshot/response groups, flush markers, ACK and backpressure.
- `lua_ui_publish()` validates and projects `cdin.ui-model.v1` into typed messages for attached clients, retains the latest semantic model and supports attach/resync publication.
- Inbound Protocol messages are dispatched to the Runtime on the Lua owner thread through `cdin_lua_host_pump()`.
- `view.request_lines` calls Runtime's line-read method; Backend Host reads exact line bytes from a Kernel Snapshot and returns `view.lines`.
- Headless frame/event replay tests, fuzz entry point and a Kernel/Lua-independent CMake/CTest path.

## 2. Remaining release blockers

### P0 — Verify the paired Runtime 1.0.0 candidate

The supplied Runtime archive was updated to Host API `1.0.0` / Frontend Protocol `1.0.0` and includes `documents.read_lines`, Runtime event dispatch, line-window handling, bounded UI Model and FakeHost/integration tests. The Backend-owned patcher is retained for applying the same integration to a clean pre-integration Runtime checkout. Lua 5.4 tests and live Kernel integration were not executable in this workspace; the GitHub workflow must verify them before production use.

### P0 — Real Lua 5.4 + Kernel end-to-end

Build with `CDIN_WITH_LUA=ON`, pinned `cdin-kernel >= 1.2.1` and PUC Lua 5.4 headers. Test Startup/Shutdown, document lifecycle, UI snapshot, key/text/paste/mouse/resize/focus, command, line reads, stale version, notification resync, ACK/backpressure, disconnect and attach snapshot. Local development dependencies were missing, so this build/test was not run here.

### P0 — Concrete Frontend transport

The codec has stream framing and partial-I/O callbacks, but the Backend has no concrete out-of-process transport. For Frontend processes, implement Unix Domain Socket on Linux/macOS and Windows Named Pipe on Windows, with explicit owner/lifecycle, peer access/authentication policy, timeout/cancel, partial I/O, bounded reads/writes and disconnect cleanup. TCP remains optional unless remote Frontends are a stated product requirement.

### P0 — Native OS matrix

The local verification is Linux-only. Require current-commit CI results on Linux, macOS and Windows for Backend build, Kernel package, Lua 5.4, lifecycle, transport and Runtime integration. Workflow definitions are not a substitute for successful job results.

### P1 — Expanded conformance/fuzzing

- Exercise every Protocol payload schema, nested maps/arrays and frame boundary under ASan/UBSan/libFuzzer.
- Extend Headless Replay to compare both directions byte-for-byte across reconnect, driver promotion, queue pressure and resync.
- Add a long-running fuzz campaign and preserve minimized regressions as corpus seeds.

## 3. Version identity and product-release gates

Backend source/API `1.0.0`, Host API `1.0.0` and Frontend Protocol `1.0.0` are the versions in this source snapshot. The source/API version freeze is separate from production integration readiness:

- retain the exported-symbol, public-struct, struct-size/version, and ownership/lifetime audit as a required release-quality check;
- keep the Backend C ABI compatibility policy explicit;
- run the paired Runtime 1.0.0 candidate Lua 5.4 tests and live Backend/Kernel integration;
- keep Protocol 1.0.0 as the shared contract and complete Runtime event/model and transport conformance before production integration;
- validate package metadata and source archives against the frozen version;
- test an independent consumer against installed artifacts and verify checksums.

The Kernel ABI 1.1.0 is consumed via its existing public header/adapter; this work does not propose a Kernel ABI change.
