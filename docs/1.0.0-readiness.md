# Backend 1.0.0 readiness — audit and blocking work

**Audited against:** `cdin-editor/backend` main at `f406ffcdd8392deec5e21df7bedaf384baf23139`, `cdin-editor/spec` release `1.1.0` at `c4de9bf3d506b4e1f07b8986531cd056341708b0`, and `cdin-editor/runtime` at `29289db83133155493766d51f64ecc02c67bb5a9`.

This document is a readiness gate, not a declaration that Backend 1.0.0 is complete. The current Backend reports version `0.1.0`; its Runtime Host API is `0.2.0` and provisional. Do not create or move a `v1.0.0` tag until every release blocker below is either implemented and verified or explicitly excluded by an accepted Spec decision.

## 1. Verified baseline

The existing repository contains a C11 Backend library, a private Kernel adapter, an optional PUC Lua 5.4 bridge, portable OS services, a session model, an in-process Frontend Protocol queue, and six integration/E2E scenarios. The checked CI run at the audited commit passed, but its Makefile reported a stub Lua build: `CDIN_WITH_LUA` was not enabled. Therefore that green CI result did **not** verify a production Runtime startup.

The existing tests cover the Kernel document workflow and in-process Frontend lifecycle/backpressure, but the Frontend queue currently transports opaque payload bytes rather than a validated semantic message schema.

## 2. Blocking implementation work

### P0 — production Runtime Host integration

- [ ] Make Lua 5.4 an explicit, required CI configuration for the release build, not `WITH_LUA=auto`.
- [ ] Run the real `cdin-editor/runtime` tree through Backend startup, notification pump and shutdown; do not use `tests/support/fake_host.lua` for this gate.
- [ ] Add live document create/read/replace/batch/undo/redo/snapshot/transaction/notification/search tests through Lua Host methods, not just the C Kernel adapter.
- [ ] Test startup failure/unwind, callback ownership, graceful/abort shutdown with accepted and in-flight work, and stale-handle finalization.
- [ ] Pin Runtime to a reviewed release/commit and update it deliberately when the contract changes.

The new `runtime-integration.yml`, `run-runtime-integration.sh`, and `runtime_host_smoke.c` add the first live startup/shutdown check. They are deliberately not presented as full document-contract coverage.

Spec links: [LIFE-001/002](https://github.com/cdin-editor/spec/blob/c4de9bf3d506b4e1f07b8986531cd056341708b0/docs/architecture/lifecycle.md#L37-L40), [BE-007](https://github.com/cdin-editor/spec/blob/c4de9bf3d506b4e1f07b8986531cd056341708b0/docs/components/backend.md#L70-L71), [Runtime Host contract](https://github.com/cdin-editor/runtime/blob/29289db83133155493766d51f64ecc02c67bb5a9/docs/contracts/runtime-host-api.md#stability-gate).

### P0 — complete Frontend Protocol request and publish path

- [ ] Define and validate the `cdin.ui-model.v1` schema at the Backend boundary.
- [ ] Translate the Runtime's model snapshot into typed messages: `ui.options`, `ui.style_table`, `ui.layout`, `view.lines`, `view.invalidate`, `ui.statusline`, `ui.prompt`, `ui.panel`, `ui.notify`, and `ui.flush`.
- [ ] Add a bounded inbound request queue and route `input.key`, `input.text`, mouse, paste, resize, focus, line-range and command requests to Runtime on the Lua owner thread.
- [ ] Preserve document versions on line/invalidation messages and discard stale view data.
- [ ] Add end-to-end tests with two clients, reconnect/detach, queue-full behavior, flush atomicity, ACK sequence validation and replay.

The current `host.ui:publish(model)` retains the latest model in the Lua registry; it does not convert the model into Protocol messages. The current Protocol public API is an in-process, outbound opaque-message queue, not a completed bidirectional Frontend interface.

Spec links: [PROTO-010/011](https://github.com/cdin-editor/spec/blob/c4de9bf3d506b4e1f07b8986531cd056341708b0/docs/architecture/frontend-protocol.md#L67-L69), [PROTO-020/023](https://github.com/cdin-editor/spec/blob/c4de9bf3d506b4e1f07b8986531cd056341708b0/docs/architecture/frontend-protocol.md#L112-L115), [FE-003/005/007](https://github.com/cdin-editor/spec/blob/c4de9bf3d506b4e1f07b8986531cd056341708b0/docs/components/frontend.md#L64-L68), [TEST-020](https://github.com/cdin-editor/spec/blob/c4de9bf3d506b4e1f07b8986531cd056341708b0/docs/testing/conformance.md#L87).

### P1 — complete Host system services

- [ ] Add native dialog requests and result delivery.

### P1 — sustained stress, memory and sanitizer verification

The new `native-stress.yml` runs the bounded worker pool on Linux, macOS and Windows, and adds ASan/UBSan and TSan jobs on Linux. The stress runner checks:

- outstanding jobs never exceed the configured capacity;
- a saturated queue produces observable backpressure;
- every accepted job completes exactly once;
- no jobs remain outstanding after graceful shutdown;
- current/peak resident set size and throughput are recorded as JSON;
- optional RSS thresholds fail the job when exceeded.

The new scheduled/manual benchmark workflow retains JSON reports as artifacts. It does not invent a performance budget: a 1.0.0 gate still needs representative baseline data and agreed regression thresholds for throughput, peak RSS, tail latency and long-duration soak behaviour.

Spec links: [BE-008/009](https://github.com/cdin-editor/spec/blob/c4de9bf3d506b4e1f07b8986531cd056341708b0/docs/components/backend.md#L71-L73), [TEST-010/011/013](https://github.com/cdin-editor/spec/blob/c4de9bf3d506b4e1f07b8986531cd056341708b0/docs/testing/conformance.md#L79-L82), [TEST-030](https://github.com/cdin-editor/spec/blob/c4de9bf3d506b4e1f07b8986531cd056341708b0/docs/testing/conformance.md#L98).

- [ ] Add a headless Frontend which records all received messages and replays scripted input.
- [ ] Add fuzzing for Host input tables, framing/decoder once selected, path normalization, file chunk boundaries and all size/range fields.

### P1 — cross-platform release matrix

- [ ] Test the complete Lua-enabled Backend + Runtime integration on Linux, macOS and Windows.
- [ ] Run the Kernel-linked scenarios and package checks on each supported target OS.
- [ ] Test static and shared library packaging, install/export metadata, runtime loader paths, and source archive reproducibility.

The existing shared Pipeline reusable CI currently executes on Linux. The added native stress matrix proves only the stress executable on each OS; it does not claim the full Kernel/Runtime release matrix is green.

## 3. Decisions that block a stable public 1.0.0 contract

Do not silently invent final public behavior for unresolved Spec decisions:

- [OD-22 — serialized protocol encoding](https://github.com/cdin-editor/spec/blob/c4de9bf3d506b4e1f07b8986531cd056341708b0/docs/adr/open-decisions.md#od-22): select a binary-safe framed representation and define canonical message schemas before implementing remote/socket transport.
- [OD-23 — protocol client library and location](https://github.com/cdin-editor/spec/blob/c4de9bf3d506b4e1f07b8986531cd056341708b0/docs/adr/open-decisions.md#od-23): explicitly approve the shared client boundary and repository location.
- [OD-24 — multi-frontend mutation ownership](https://github.com/cdin-editor/spec/blob/c4de9bf3d506b4e1f07b8986531cd056341708b0/docs/adr/open-decisions.md#od-24): accept or replace the provisional driver/observer rule.
- [OD-32 — Lua-to-native bridge](https://github.com/cdin-editor/spec/blob/c4de9bf3d506b4e1f07b8986531cd056341708b0/docs/adr/open-decisions.md#od-32): choose PUC Lua 5.4 C API, LuaJIT FFI or another documented bridge based on tested platform/deployment evidence.

If the first 1.0.0 release is deliberately in-process-only and embeds the GUI in the same process, OD-22/OD-23 can be marked out of scope for that release only after the Spec owner records that scope explicitly. Do not advertise a serialized/remote protocol in that case.

## 4. Release engineering gate

- [ ] Decide the stable public C ABI and Host API versioning policy; the current `0.x` Host API is provisional.
- [ ] Audit ABI layout, struct-size extension rules, ownership, allocator boundaries, callback lifetime, thread affinity and error/status stability.
- [ ] Decide whether 1.0.0 requires an ABI-major break from 0.1.0 or a compatible transition; document migration and compatibility policy.
- [ ] Set the version fields, CMake project version, package metadata, changelog and tag together only after the API freeze.
- [ ] Build and inspect release archives on each supported OS, verify SHA-256 sidecars, and run a clean consumer project against installed artifacts.
- [ ] Run all checks on the exact release tag commit before publication.
- [ ] Record the final test matrix and known limitations in the release notes.

## 5. Commands introduced by this preparation bundle

```sh
# Bounded queue pressure, RSS and throughput report
bash scripts/run-resource-stress.sh --seconds 30 --workers 4 --capacity 128 --output build/stress/report.json

# Live PUC Lua 5.4 + production Runtime check (after checking out runtime/ and installing deps)
make deps
bash scripts/run-runtime-integration.sh

# Full local gate remains the repository's existing task
bash scripts/ci-check.sh
```

Pipeline tasks `stress` and `benchmark` are appended by `apply.sh` when the bundle is applied.
